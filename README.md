# Beetroot Academy — Embedded Development (ESP32-S3)

PlatformIO-проєкт для ESP32-S3 DevKitC-1.
У `src/` — поточне завдання, попередні — в `homework/`.

## Поточне ДЗ 3.3: Широтно-імпульсна модуляція (PWM) — ESP-IDF

Потенціометр керує яскравістю світлодіода і швидкістю двигуна ([src/main.c](src/main.c)).

- ADC1 oneshot кожні 20 мс + SMA на 8 вимірювань (з ДЗ 3.1) — стабільне значення потенціометра;
- ШІМ — драйвер ESP-IDF **LEDC**, розрядність 10 біт (0…1023);
- **LED**: заповнення лінійно 0…100 % від положення потенціометра;
- **двигун**: мертва зона внизу (< 5 % — вимкнений, як у прикладі з уроку), далі заповнення від 39 % (≈400/1023) до 100 % — при меншому двигун гуде, але не рушає.

### Як двигун і світлодіод не впливають одне на одного
| Рівень | Рішення |
|---|---|
| Програма | у кожного свій таймер і канал LEDC: LED — timer 0, 5 кГц; двигун — timer 1, 20 кГц. Зміна одного не чіпає інший |
| Живлення | двигун живиться від окремої плати живлення 5 В, ESP і LED — від USB. Спільна лише земля |
| Завади | діод паралельно двигуну гасить викиди напруги; конденсатор 100 мкФ згладжує просадки живлення при старті двигуна |
| Вимірювання | SMA згладжує завади від двигуна на ADC — яскравість LED не «смикається» |

### Схема
| Елемент | Підключення |
|---|---|
| Потенціометр | крайні ніжки — **3V3 ESP** і GND, повзунок — GPIO2 |
| LED | GPIO4 → 220 Ом → LED → GND |
| Транзистор 2N2222 | GPIO17 → 220 Ом → база; 10 кОм база → GND; емітер → GND; колектор → (−) двигуна |
| Двигун | (+) → +5 В плати живлення |
| Діод | паралельно двигуну, смужкою (катодом) до +5 В |
| Конденсатор 100 мкФ | (+) до +5 В, (−) до GND |
| Земля | GND плати живлення з'єднаний з GND ESP |

### Висновки
- **Яскравість LED** лінійно повторює положення потенціометра: 2 % → 2 %, 50 % → 50 %, 100 % → 100 %.
- **Двигун**: до 5 % — вимкнений (мертва зона), з 6 % одразу стартує з 39 % заповнення і плавно розганяється до 100 %.
- **Незалежність**: коли ручка нерухома, а двигун крутиться, значення тримається в межах ±0.2 % (2126…2134) — завади від двигуна не впливають ні на ADC, ні на яскравість LED.
  Кожен вихід має свій таймер LEDC з власною частотою (5 кГц і 20 кГц), тож зміна одного не чіпає інший.
## Попередні завдання (`homework/`)
- `adc_calibration/` — ДЗ 3.2: калібрування ADC, похибка формули, графік нелінійності;
- `sma/` — ДЗ 3.1: SMA-фільтр для LDR на ESP-IDF, гістерезис;
- `miniproject_automotive/` — міні-проєкт (модуль 2, урок 7): замок, аварійка, поворотники, датчик удару; DL → CL → BL;
- `debounce_idf/` — ДЗ 2.6: debounce на ESP-IDF, state-based на апаратному таймері `gptimer`;
- `timers/` — ДЗ 2.5: апаратний таймер керує витяжним вентилятором (реле), watchdog, лог, LED;
- `debounce/` — ДЗ 2.4: 4 методи debounce + RC-фільтр, порівняльна таблиця;
- `superloop/` — ДЗ 2.3: три незалежні LED (200 / 500 / 1000 мс) у superloop на `millis()`;
- `relay/` — вимірювання часу спрацювання реле (`micros()` + переривання), результати 10 вимірювань;
- `motor_control/` — код з уроку: PWM-керування DC-мотором через транзистор, команди off / low / mid / high з Serial;
- `embedded_blink/` — Blink в стилі Embedded C++: `enum class`, `static constexpr`, кнопка через переривання, час `loop()`;
- `headlight_hazard/` — Варіант 2: адаптивна фара (LDR) + аварійна сигналізація, схема та симуляція Wokwi;
- `1.5_bounce.cpp` — дослідження брязкоту кнопки через переривання;
- `1.6_ldr_alt.cpp` — LDR, АЦП і похибка `analogRead()` vs `analogReadMilliVolts()`;
- `police_flasher.cpp` — поліцейська мигалка.
